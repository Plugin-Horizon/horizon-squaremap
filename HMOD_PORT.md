Round 5 (100 % brief, blind, no compile; hmod-format branch)
- Fixed: every level, not only the three vanilla dimensions. The fixed `DIMENSIONS`, `WORLDS` and `SHAPES` tables are gone. `src/horizon_squaremap/runtime.rs` keeps a level registry (`LEVELS`, `set_open_levels`, `world_index`, `open_world_index`, `open_levels`, `world_name`, `level_ids`, `world_enabled`, `level_shape`): a level gets an index the first time it is seen and keeps it for the process, with its open flag and the height range the host gave it. `src/lib.rs` `sync_levels` feeds it from `host.levels().list_levels()` at `server_started`, `level_load` and `level_unload` (the event's level added or removed), reads `LevelRef.height` for each open level, and resumes the renders a stop interrupted (`resume_renders`). A level that closes keeps its index, queued work and render job, as the original keeps its region files.
- Fixed: per-world settings for any level. `config.world(id)` already merged `world-settings.default` with `world-settings."<id>"` (the original's per-key fallback); the runtime now builds a worker per registered level, and `json::settings` lists the open levels whose `map.enabled` is on, with `type` `normal`/`nether`/`the_end`, or `custom` for any other (`WebSettingsPublisher.environment`).
- Fixed: commands take any open level. `parse_world` and the completions use the registry; `resetmap` lists every open level, the other world commands only the enabled ones (`MapWorldParser`). `world_id` is the level's identifier, so messages name `mod:castle`.
- Fixed: `/squaremap resetmap <world>` on a level whose map is disabled resets it (the original's `ResetMapCommand`: no enabled check). The tiles folder is emptied (and made when missing), the cached documents under `/tiles/<world>/` are forgotten, the settings document is written only when the map is on, and the success line is sent. Before: refused with "Map is not enabled".
- Fixed while doing it: `cancelrender` and `pauserender` on a disabled level answer "Map is not enabled for world '<world>'" (the original's `MapWorldParser` refusal) instead of "No renders running" or "Paused renders". A disabled level is no longer drawn: its chunks are not queued, its markers are not published and its players are left out of `players.json` (before, the background pass drew every level).
- Checklist round 100 (round 5 state): the two round-4 open items below are done.
- Unsure: (1) the registry order is the order levels were first seen; the original lists worlds in a hash order and the frontend sorts by `order`. (2) A custom level's ceiling is vanilla's (only the nether has one): the host gives no dimension-type ceiling read. (3) `level_unload` removes the closing level from the open list even if `list_levels` still reports it. (4) `reset_map` for an enabled level writes its settings with spawn `[0, 0]` as before; the next markers tick publishes the real spawn.
- Tests (literal values): `json::documents_have_squaremaps_shape` (open-level list, `nether`/`the_end` types), `config::a_custom_level_has_its_own_section_and_the_default_for_the_rest`, `web::clear_forgets_only_the_prefix`, `runtime::tests` (index kept across unload, host height over vanilla, unknown index), `commands` tests (`parse_world` for `the_nether`, `mod:castle`, `castle`, `nether`; completions for resetmap and the others). Registry tests share `runtime::REGISTRY_TESTS` and open the same four levels. No test covers the disabled-level reset itself: it needs the running map (`reset_map`), which unit tests cannot start.

Round 3 (blind, no compile)
- Fixed: background redraw of changed chunks (`src/horizon_squaremap/runtime.rs` `due_chunk`, `world_saved`, `Work::Disk`; `src/lib.rs` `world_saved` hook): a changed chunk that is still loaded waits for the next world save and is then drawn by the render thread from the region files; one that unloaded meanwhile is drawn from them at once. Before, the mark was consumed and the tile redrawn from the old save.
- Fixed: the bare label answers `Invalid command syntax. Correct command syntax is: /squaremap <cancelrender|confirm|...>` (cloud's answer), with the special characters in white; `invalid_syntax` highlights them for every command.
- Fixed: `/squaremap help` is paged (six to a page, page number ends the query), has a title bar, `Available Commands:`, search-result captions, `\u{2190} n/m \u{2192}` page links, and one command's `Command`/`Description`/`Arguments` view (entries sorted by syntax as cloud's index; `hide` and `show` list `<player>` as a second entry). The bar and arrows are written from memory of cloud-minecraft-extras: the layout is close, not byte-identical.
- Fixed: `radiusrender`'s centre reads `<x> <z>` as numbers, `~` offsets or `^left ^forward` local coordinates (along the sender's facing); mixing the forms and bad input give squaremap's location messages (`commands::center`).
- Added: `plugins/squaremap/config.yml` and `advanced.yml` are read (a small YAML reader, `yaml.rs`) and laid over `config/squaremap-server.toml`; `settings.language-file` and `plugins/squaremap/locale/<file>` replace the command messages by their original keys (`render-in-progress`, `command.message.*`, `command.hide.*`, `plugin-reloaded`, the help captions `command.message.help.*`, ...). MiniMessage colour/click tags in a language file are dropped: the wording and the `<placeholders>` follow the file, the colours stay squaremap's defaults. `/squaremap reload` reads the language file again.
- Left open: more than the three dimensions and `resetmap` on any level (`WORLDS`, `SHAPES` and the JSON tables are fixed to three levels; needs a level registry through the whole runtime); `hide`/`show` take Horizon's `player` argument, so the selector grammar and its error texts are the engine's, not squaremap's; custom colours and click tags of language files; region compression LZ4; biome zoom/swamp noise for saved chunks; nickname.
- Unsure: (1) cloud sorts a command node's children alphabetically (the `<...|...>` list). (2) `Part.hover` is now an owned `String`. (3) `WorldSavedEvent` fires after the chunks reached the region files. (4) `entity.rotation(host)` yields `[yaw, pitch]`.
